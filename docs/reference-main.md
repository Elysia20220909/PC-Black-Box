## 基本操作

- ファイルまたはフォルダーを1つ、ウィンドウへドロップするか、選択ボタンを使います。
- `調査開始`を選びます。
- `概要`で全体評価と主要な指摘を確認します。
- `ファイル`で署名、入手元、ハッシュ、形式、ファイルごとの根拠を確認します。
- `レポート`で内容を確認してコピーするか、MarkdownまたはJSONとして保存します。
- 調査中に`Esc`を押すと停止します。

`JA / EN`で表示言語を切り替えられます。保存される設定は言語だけで、場所は`%LOCALAPPDATA%\PCBlackBox\settings.json`です。

| 操作 | キー |
|---|---|
| ファイルを選ぶ | `Ctrl+O` |
| フォルダーを選ぶ | `Ctrl+Shift+O` |
| ファイル一覧を検索する | `Ctrl+F` |
| 調査を始める | `F5`または`Ctrl+Enter` |
| 概要 / ファイル / レポートを切り替える | `Ctrl+1` / `Ctrl+2` / `Ctrl+3` |
| 表示言語を切り替える | `Alt+L` |
| 調査を止める | `Esc` |

指摘カードはクリックするか、TabでフォーカスしてEnter / Spaceを押すと、根拠になったファイルを表示できます。ファイル一覧では名前、形式、署名、署名者、入手元、指摘を検索でき、`高 / 確認 / 低 / 所見なし`で絞り込めます。

## 調査するもの

| 領域 | 調べる内容 | 重要な境界 |
|---|---|---|
| ダイジェスト | ファイル全体のSHA-256 | 能力語スキャンの容量制限とは独立して計算する |
| ローカル信頼 | Authenticode状態、署名者、製品名、会社名 | Windowsの`WinVerifyTrust`を失効確認なし / URLキャッシュ限定で使い、現在のオンライン失効状態は確認しない |
| 入手元 | Mark-of-the-WebのInternet Zoneと入手元ホスト | 存在しない入手元情報を推測しない |
| 実形式 | マジックバイト、拡張子との不一致、PEアーキテクチャ | ファイル名だけを信用しない |
| 名前の偽装 | 二重拡張子、右から左への制御文字、不可視文字、Windowsが除去する末尾空白・ピリオド | 表示名と実効拡張子を分けて扱う |
| Windowsショートカット | 対象、引数、作業フォルダー、非表示起動、昇格要求 | `.lnk`構造を読み、解決や起動はしない |
| PE / スクリプト / PDF | ダウンロード、永続化、Defender変更、プロセス注入、隠し実行、削除などの能力語 | 明示した容量 / 時間制限内でストリーム走査する |
| OLE複合ファイル | MSI / MSP / 旧Officeなどで使われるOLE形式を認識し、生バイト内の文字列を走査 | 内部ストレージ木、MSIテーブル、VBAは解析しないため、構造面は`INCOMPLETE`になる |
| ZIP / Officeパッケージ | 前置データ、ポリグロット、内部二重拡張子、能動コンテンツ、パストラバーサル、異常圧縮率、宣言サイズと実測EOFの差 | 標準パーサーへ渡す前に境界を検証し、ディスクへ展開しない |
| 入れ子ZIP | 別拡張子に隠れたものを含む、有効なZIP構造の再帰調査 | メモリ内で深さ3まで。未対応、破損、暗号化、読取不能、上限超過は`INCOMPLETE` |

PEエントロピーは先頭8 MiBから計算します。SHA-256や、対応形式に対する能力語スキャンが8 MiBで止まるという意味ではありません。

## 判定の読み方

PC Black Boxは、リスクと完全性を別々に評価します。

### リスク

| 表示 | 点数 | 意味 |
|---|---:|---|
| `CLEAR` | 0 | 対応する調査では、注意すべき指摘を検出しなかった |
| `LOW` | 1–24 | 低い重みの指摘があり、文脈確認が必要 |
| `REVIEW` | 25–59 | 実行前に証拠を確認すべき |
| `HIGH` | 60–100 | 対象を閉じたまま優先確認すべき強い証拠がある |

点数は指摘の重みを足し、確認順を決めるためのものです。感染確率ではありません。正規の管理スクリプト、インストーラー、圧縮ツールでも警告は出ます。反対に、未知のコードが静的調査で手掛かりを残さないこともあります。

### 完全性

| 観点 | 確認する範囲 | `INCOMPLETE`になる例 |
|---|---|---|
| 探索 | 選択対象内の全ファイルへ到達できたか | 列挙上限、リパースポイント、調査中のフォルダー変更 |
| ダイジェスト | 到達したファイルの全バイトがSHA-256へ入ったか | 安全に開けない、読取中に変更された |
| 能力語の内容走査 | 対応形式を適用境界まで走査したか | 容量 / 経過時間 / 照合時間の上限 |
| 署名 | 適用可能な全署名を確認したか | 1回の調査で署名候補が300件を超えた |
| 構造 | ZIP、ショートカットなどの内部構造を調べたか | 読取不能アーカイブ、破損構造、未解析OLE内部 |

`COMPLETE`は、対応する調査が安全上限内で完了したという意味です。対象が安全という意味ではありません。

既知の指摘と未調査範囲は同時に残り、`HIGH+INCOMPLETE`のように表示されます。リスク指摘がなくても完全性が足りなければ、`CLEAR`ではなく`INCOMPLETE`です。

## 主な調査上限

上限は、細工された入力や巨大フォルダーによる資源枯渇から調査処理を守ります。上限到達、読取失敗、解析時間超過が起きた範囲は`INCOMPLETE`となり、`CLEAR`にはなりません。

### フォルダーと通常ファイル

| 対象 | 上限 |
|---|---:|
| ファイル | 2,500 |
| フォルダー | 10,000 |
| フォルダー深度 | 128 |
| 列挙エントリ | 20,000 |
| 保持するパス情報 | 8,388,608文字 |
| 対象全体のサイズ | 12 GB |
| 署名検証 | 1回につき300ファイル |
| 能力語スキャン | 1ファイル1 GiB / 1回4 GiB |
| 能力語スキャン時間 | 1ファイル60秒 / 1回180秒 |
| PEエントロピー | 先頭8 MiB |

リパースポイントは追跡しません。ファイルとフォルダーは、リンクを追わないハンドルと最終パス照合で確認します。

### Windowsショートカット

| 対象 | 上限 |
|---|---:|
| 読み取るショートカット本体 | 4 MiB |
| 文字列ごと | 8,192文字 |
| LinkInfoから内容を抽出する範囲 | 64 KiB |
| ExtraData | 64ブロック |

### ZIPとZIP系パッケージ

| 対象 | 上限 |
|---|---:|
| 最上位ZIP入力 | 2 GiB |
| ZIPごとのエントリ一覧 | 10,000件 |
| 中央ディレクトリとZIP64終端拡張データ | 64 MiB |
| 中央エントリ名 / 解析後パス | 4,096バイト / 2,048文字 |
| エントリ本文走査 | 1エントリ64 MiB / 最上位ZIPと入れ子全体256 MiB / 1回1 GiB |
| 1回の圧縮入力読取 | 64 KiB |
| 入れ子ZIP | 深さ3 / 1ファイル32個 / 再帰エントリ20,000件 |
| メモリ保持する入れ子ZIP | 1個32 MiB / 1ファイル128 MiB |
| ZIP本文走査時間 | 最上位ZIPごと30秒 / 1回120秒 |

上限に達したエントリが続くことを証明するときだけ、最大1バイトを追加で読みます。時間上限は各ソース読取の前後で確認しますが、すでに実行中のOS読取や展開処理を途中で必ず止められるものではありません。

実測EOFから対象本文の総量を確定できない場合、推測した分母は表示せず、総量を不明として走査量だけを報告します。共有上限を使い切った場合は、未読本文の件数と、そのうち名前上で能動コンテンツや別コンテナを示すものを画面 / Markdown / JSONへ残します。これは未調査範囲の名前による棚卸しであり、本文形式や安全性の証明ではありません。

## プライバシーと安全境界

- 対象を実行せず、コードとして読み込みません。
- 対象もレポートもアップロードしません。
- 自動通信やブラウザー起動を行いません。
- プロセス注入、ゲームメモリ読取、パケットキャプチャを行いません。
- ファイルを削除、隔離、移動、修復しません。
- レポートから、この環境の絶対パス、Windowsユーザー名、IPアドレス、Steam ID、認証情報を除外します。

ショートカットの対象や引数など、調査対象自身に保存された文字列は証拠としてレポートへ現れる場合があります。レポートには調査したファイル名、入手元ホスト、SHA-256も含まれるため、それ自体を機密情報として扱ってください。GUIの既定名と、`reports/`、`pc-black-box-*.md`、`pc-black-box-*.json`、`*.report.md`、`*.report.json`に一致するレポートは`.gitignore`で除外されます。任意の名前は除外されない場合があるため、Gitへ追加する前と共有前に内容を確認してください。

`SHA-256をコピー`と`照会URLをコピー`は文字列をクリップボードへ置くだけです。PC Black BoxはURLを開かず、サービスとも通信しません。利用者が別途そのURLを開くと、SHA-256がVirusTotalへ送られます。Windowsのクリップボード履歴が有効なら、コピー内容が保存され、設定によってはMicrosoftアカウント経由で同期されることもあります。

## 多層防御

調査入力は信頼しません。PC Black Boxは通常のアプリ初期化前に、`SECURITY-BASELINE-2`の必須16項目を設定または検証し、利用可能な確認手段で必須姿勢の成立を判定します。ひとつでも成立を確認できなければ調査を始めません。

| 層 | 主な保護 |
|---|---|
| 権限 | 管理者起動を拒否し、子プロセス作成を禁止する |
| プロセス | DACLにより、同一ユーザーから新たに要求されるメモリの読み取り / 書き込み、スレッド作成、ハンドル複製を拒否する |
| メモリ / 制御フロー | DEP、ASLR、Control Flow Guard、SEHOP、厳格なハンドル確認、ヒープ破損時終了を必須にする |
| DLL読込 | P/Invokeの既定探索をSystem32に限定する。通常DLL探索はアプリフォルダーとSystem32に絞り、カレントフォルダー、UNC、Low-integrityイメージを除外する |
| ランタイム | Hot Reloadのメタデータ更新経路とEventSourceトレース面を無効にする |
| ネットワーク境界 | 固定リストにある送信可能な標準.NET通信アセンブリが未読込であることを確認し、後からロードを検出した時点でプロセスを停止する |
| ファイルI/O | リンクを追わない安定ハンドルを使い、最終パス、サイズ、更新時刻、ボリューム番号、128bitファイルIDを再確認する |
| 保存 / 列挙 | 親フォルダーの削除共有を拒否し、列挙後にフォルダーIDと更新時刻を再確認する |
| パーサー | ZIP終端と中央ディレクトリを事前検証し、件数、長さ、入力サイズ、再帰経路、正規表現評価をすべて制限する |

OSとCPUが対応する場合は、リダイレクト信頼、セキュリティドメイン分離、ページ結合無効化、投機的ストアバイパス無効化も適用して読み戻します。ハードウェアシャドースタックは読み取り専用で観測します。利用できない強化策は、有効と仮定せず`unavailable`と報告します。

画面とレポートには必須ベースラインを`16/16`として示し、その端末で有効な強化策を続けて表示します。全制御、検証限界、残余境界、採用しなかった対策と理由は[脅威モデル](../THREAT_MODEL.md)に記録しています。

この設計は、Appleが重視するコード信頼と能力境界の考え方を、現在のWindows / WPFで実装できる防御へ置き換えたものです。iOS App Sandboxと同じ隔離や、外部機関による認証を意味するものではありません。

## 現在の限界

- 静的調査です。動的サンドボックスや実行時通信先の観測は行いません。
- WPFプロセスはAppContainerではありません。
- 管理者、カーネル侵害、改変されたWindows信頼ストア、悪意あるファームウェア、物理アクセスは保護境界外です。
- プロセスDACLはロックダウン後の新しいアクセス確認へ作用します。起動元が事前に保持したフルアクセス・ハンドルは取り消せません。
- 標準.NET通信アセンブリの監視は、AppContainerやWindows Filtering PlatformによるOSレベルの能力除去ではありません。将来ネイティブ通信を追加すれば迂回できるため、その変更は許容するソース範囲外です。
- ZIP本文はディスクへ展開せず、有効な入れ子ZIPを共有上限内で再帰調査します。マルウェア署名エンジンでも実行時サンドボックスでもありません。
- 入れ子の7-Zip / RAR / GZip / Cabinet / OLE / ISO、破損ZIP、暗号化ZIP、上限超過や読取不能のZIP内部は開かず、`INCOMPLETE`にします。
- 前置データ付きZIP / ZIP64は制限内で復元して調査しますが、前置部分は未解析のため`INCOMPLETE`です。
- PDF / PE / スクリプトなどとのZIPポリグロットは両方の調査面を保持します。宣言本文サイズは信用せず、実測EOFとの差を`INCOMPLETE`として報告します。
- 分割ZIP、暗号化中央ディレクトリ、曖昧な複数EOCDは警告し、内部調査は行いません。
- スクリプトのコメントも能力語に一致するため、指摘には文脈確認が必要です。
- VirusTotalなどの外部評判情報、複数ウイルス対策エンジン、クラウド既知ハッシュ、動的解析は含みません。
- `CLEAR`は安全保証ではありません。

`NSA級`のような表現は、この製品が持たない認証を想起させます。ここでいう高強度化は、公開仕様に基づく多層制御と、必須姿勢を確認できなければ調査しないフェイルクローズ設計を指します。

## 開発と検証

すべて管理者ではないPowerShellで実行します。管理者起動は専用メッセージと終了コード1で拒否されます。

```powershell
dotnet build .\Destiny2BlackBox.csproj -c Release
dotnet ".\bin\Release\net10.0-windows10.0.17763.0\PC Black Box.dll" --security-status
dotnet ".\bin\Release\net10.0-windows10.0.17763.0\PC Black Box.dll" --self-test
```

外部プロセスから境界を確認するテストは、次のコマンドです。現在のスクリプトは引数なしでアプリを起動するため、GUI禁止の環境では実行せず、未検証として記録してください。`-WindowStyle Hidden`はヘッドレス実行の保証ではありません。

```powershell
pwsh -NoProfile -File .\tests\Test-RuntimeBoundaries.ps1
```

| ゲート | 必須結果 |
|---|---|
| Releaseビルド | 警告0 / エラー0 |
| `--security-status` | `enforced=true controls=16/16` |
| `--self-test` | `PC_BLACK_BOX_SELF_TEST passed=true` |
| `Test-RuntimeBoundaries.ps1` | `PC_BLACK_BOX_RUNTIME_BOUNDARY_TEST passed=true` |

Markdownレポートだけを生成する場合は、次のようにします。

```powershell
dotnet ".\bin\Release\net10.0-windows10.0.17763.0\PC Black Box.dll" --report "C:\path\to\target" ".\inspection.report.md"
```

`--self-test`は一時フォルダーと検証用ファイルを自ら作成し、終了時に削除します。ローカルビルド出力は`bin/`に作られますが、配布物として登録されません。
