# 手動GUI検証の準備と切り戻し

この手順はローカル検証用です。配布用EXE、署名付き製品版、インストーラーを生成しません。既存のRelease出力を別の検証フォルダーへコピーします。GUIの合格や配布許諾を証明するものではありません。

## 準備

通常権限のPowerShell 7と.NET 10 Windows Desktopランタイムを使用します。先に本体とDiEブリッジのRelease出力を、検証したソースから用意してください。スクリプト自体はビルドもダウンロードもしません。

リポジトリのルートで実行します。`$oldRoot`、`$engineArchive`、`$expectedHead`、`$appSha256`、`$bridgeSha256` は、手元で確認した既存版の場所、公式DiE 3.21アーカイブの場所、対象ソースSHA、検証済み本体DLLとブリッジDLLのSHA-256を設定してください。未確認のバイナリをその場でハッシュしただけでは、検証済みにはなりません。

```powershell
$options = @{
    RunId = 'manual-check-01'
    OldRoot = $oldRoot
    EngineArchive = $engineArchive
    ExpectedHead = $expectedHead
    AppSha256 = $appSha256
    BridgeSha256 = $bridgeSha256
}
./tools/New-GuiValidation.ps1 @options
$runRoot = Join-Path $PWD 'obj/gui-validation/manual-check-01'
./tools/Start-GuiValidation.ps1 -RunRoot $runRoot
```

`New-GuiValidation.ps1` は次の場所から読み取ります。

- `bin/Release/net10.0-windows10.0.17763.0`
- `tools/DieBridge/bin/Release/net10.0-windows10.0.17763.0`
- 引数で指定した既存版とDiEアーカイブ

出力先は `obj/gui-validation/<RunId>` です。既存のRunIdは上書きせず停止します。失敗途中のフォルダーも自動削除せず残すため、原因を確認してから別のRunIdで再実行してください。検証フォルダーのアクセス権は現在のユーザーだけに限定します。

manifestには対象SHA、準備時のソース変更有無、コピーしたファイル、旧版、共有設定のハッシュを記録します。これは取り違えの検出用であり、ビルド元の証明や署名付き改ざん検出ではありません。変更がある作業ツリーでも準備できますが、`sourceDirty=true` を記録し、HEADだけで検証対象を説明しないでください。

EXE/DLL、エンジンZIP、manifest、ログ、レポートはGit管理外に置き、コミットしません。manifestには個人用のパスが含まれます。

## 手動起動

照合だけなら `-Launch` を付けません。GUIを実際に開く場合だけ次を実行します。

```powershell
./tools/Start-GuiValidation.ps1 -RunRoot $runRoot -Launch
```

ランチャーは照合後、`dotnet.exe` に検証フォルダーの `runtime/DieBridge.dll` を渡し、ブリッジが本体との接続を用意します。`runtime/app/PC Black Box.exe` を直接開くとDiE接続は設定されません。

管理者として起動しないでください。実行ポリシー、SmartScreen等に拒否された場合は、文言を記録して停止します。保護の無効化や警告の回避はしません。アプリを閉じるまでPowerShellを開いたままにしてください。

## チェック表

初期状態はすべて未確認です。日時、実際の表示、期待した表示、再現回数を実施した項目だけ記録します。

| 項目 | 確認内容 | 結果 |
|---|---|---|
| 初期表示 | 起動時のエラーと、検査前の保存ボタンが無効であること | 未確認 |
| ウィンドウ | 最小化から戻す、最大化と復元、表示崩れ | 未確認 |
| 単一ファイル | `samples/first.txt` の本体結果とDiE解析／後始末状態 | 未確認 |
| 保存 | `reports` 内の新しい名前でMarkdown／JSONを保存し、対象とDiE状態が一致 | 未確認 |
| 連続検査 | `samples/second.txt` へ切り替え、古い結果が残らない | 未確認 |
| フォルダー | `samples/folder` でDiEのスキップ理由を確認 | 未確認 |
| 停止 | 検査中に停止し、古い結果／部分結果を保存できないこと | 未確認 |
| 停止後 | 別サンプルの検査と保存が復帰すること | 未確認 |
| 保護状態 | アプリ内のDefender照会で、履歴0件や取得失敗を安全判定としないこと | 未確認 |
| 終了 | 閉じる操作後、ランチャーが戻ること | 未確認 |

小さいサンプルで停止に間に合わなければ、その項目は未確認です。マルウェアや大量の実データを追加しないでください。DiEの削除失敗、Defender取得失敗の表示は実際に発生した場合だけ確認し、保護を無効にしたり権限を壊したりして故障を作らないでください。

言語設定は既存版と共有します。言語切替は行わないでください。終了後、ランチャーを `-Launch` なしで再実行して既存版と設定を照合します。起動前の照合は実行中の変更を防止しません。変更を検出しても、設定を自動で戻しません。

## ログと障害時の記録

起動ごとに `logs/run-日時-識別子` を作り、開始情報、ブリッジPID、標準出力、標準エラー、終了後の終了コードを保存します。起動前の照合エラーはログ作成前なのでPowerShellの文言を手動で記録してください。突然の終了やPowerShell中断ではログが欠ける可能性があります。

通常GUIではブリッジが本体の標準出力／標準エラーを明示的に収集しないため、GUI内部の例外をすべて取得できる保証はありません。空のログ、終了コード0、`finished.json` の存在だけでGUI合格とは扱いません。

発生時刻とタイムゾーン、サンプル名、操作順、実際の表示を記録し、保存できる場合のみ検査レポートを残します。画面の記録は利用者が対象画面だけを撮影します。ログには個人パスが含まれ得るため、外部へ渡す前に確認してください。自動送信、全イベントログ収集、メモリダンプ取得は行いません。

## 旧版へ戻す

検証版を閉じ、ランチャーが終了したことを確認してから、準備時に指定した `OldRoot` 直下の `PC Black Box.exe` を手動で開きます。`app` 内のEXEではなくルートのランチャーを使用します。旧版のファイル、ショートカット、既定の起動先は変更しないため、ファイル置換や再インストールは不要です。旧版には新しい修正が含まれない場合があります。

応答しなければ別版を重ねて起動せず、状態と `process.json` を記録して相談してください。他の `dotnet` プロセスを一括終了しないでください。強制終了後の一時データ削除は未確認として扱います。

検証フォルダーは `obj` にあるためclean等で失われ得ます。ソースと手順書はGitに保存しても、実行証拠やバイナリのバックアップにはなりません。必要なローカル記録の保管は別に行ってください。

実施済みと未実施の区別は [準備の検証記録](gui-validation-results.md) を参照してください。
