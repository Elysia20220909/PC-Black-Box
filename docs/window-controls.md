# ウィンドウの基本操作

右上に最小化、最大化／元に戻す、閉じるのボタンを配置しています。説明と読み上げ名はアプリの日本語／英語設定に追従し、最大化の状態が変わると復元用の表示へ切り替わります。

タイトルバーのドラッグ移動、ダブルクリックによる最大化／復元、右クリックのシステムメニュー、枠でのサイズ変更はWPFの `WindowChrome` に任せています。独自の `DragMove` 処理と透明ウィンドウ設定は外し、既存の配色と独自ボタンを維持しました。ボタン領域はタイトルバーのドラッグ領域から除外しています。

実装の根拠は [MicrosoftのWindowChrome資料](https://learn.microsoft.com/ja-jp/dotnet/api/system.windows.shell.windowchrome?view=windowsdesktop-10.0) です。OS設定、Defender連携、ファイル検査の安全境界は変更していません。

## 検証対象と限界

対象は `Destiny2BlackBox-defender-readonly` のソースと、そこから生成する `bin/Release/net10.0-windows10.0.17763.0/PC Black Box.dll` です。別ツリーの署名済みEXEやデスクトップのショートカットは更新しません。

自己テストには、最大化／復元の状態選択と日英ラベルの7検査を追加しています。ウィンドウを生成・表示しない純粋なロジック検査であり、実際のクリックやOSのウィンドウ制御を検証するものではありません。XAMLの3ボタンのハンドラー接続、タイトルバー内の入力設定、キャプション高さも読み取り検査の対象です。

GUI操作、ボタンの見た目、読み上げソフト、複数モニター、DPI切り替え、タスクバーとの位置関係、最大化後のドラッグ復元は未検証です。これらを確認済みとは扱いません。配布物は生成せず、ローカルビルドには `UseAppHost=false` を指定します。
